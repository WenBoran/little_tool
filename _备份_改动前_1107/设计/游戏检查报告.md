# 一手好菜：游戏检查报告（2026-11-07）

检查方式：按 Claude-Code-Game-Studios 的 `/project-stage-detect`、`/design-review`、`/balance-check`、`/tech-debt` 四个技能的检查清单，读了 `设计/` 下两份文档和 `_cook/` 全部规则代码（l1–l3），并在本地跑了项目自带的测试和模拟器（每组 300 局）。界面代码（u*.js、css）只看了和规则相关的部分。

## 一、现状一句话

规则引擎完整、测试全过（71 项扩展回归 + 菜谱验算 + 出锅去向验算），两个发布版本和源码一致。最大的问题在玩法层：**牌组会被打光**，自动对局 91% 死在第 2 关；而《主线方案》里已经定下的几条改动，代码里大部分还没做。

## 二、问题（按严重程度）

### 1. 出过的牌永久消失，第 2 关牌组就见底（严重）

`l3.js` 的 `consume()` 会把打出的原料、手法从牌组里删掉。模拟结果：

| 时间点 | 平均牌组张数 |
|---|---|
| 开局 | 30 |
| 第 1 关结束 | 26 |
| 第 2 关第 2 回合 | 21 |
| 死在第 2 关第 2 回合的局 | 7.6 张，其中原料 1.3 张 |

每回合用掉约 11 张牌，商店每回合只补进约 7 张。死在第 2 关的局里，约 40% 是“手里没原料、也没法弃牌”直接卡死，而不是分数不够。

我把 `consume()` 临时关掉（不改你的文件，在副本上跑）做了对照：同一套自动策略从“平均到第 1.94 关、0% 通关”变成“平均到第 3.73 关，18% 的局能打过第 4 关”（如果再按方案改成 4 关通关，通关率就是这 18%），死亡原因也从卡死变成分数不够。这说明牌组消耗是现在的头号瓶颈。

《主线方案》第四节写的是“按你选的，出过的牌和装备一样回到弃牌堆”，但代码还是消耗制，注释也还写着“用掉的牌从牌组里永久去掉”。

### 2. 《主线方案》和代码不一致（严重）

| 方案条目 | 代码现状 |
|---|---|
| 开局选招牌菜 | 未做，`START_RECIPES` 固定是煎蛋 |
| 熟练度 3/7/12 次升级 | 已做（`CFG.mastery = [3,4,5,6,7]`，累计正好是 3/7/12） |
| 买菜谱附带食材 | 未做，`buyFrom()` 只加菜谱不加牌 |
| 商店按菜谱进货 | 未做，`rollShop()` 完全随机 |
| 菜谱统一改成“分 + 倍” | 未做，煎蛋仍是 +5 分 |
| 出过的牌回弃牌堆 | 未做（见第 1 条） |
| 去掉补货包 | 未做，补货包仍在且权重最高（3） |
| 4 关通关 | 未做，`CFG.levels = 8`，终局目标 1350 分 |

另一份文档《菜谱与伙计实现清单》写“通过第 8 关通关”，和代码一致，但和《主线方案》的 4 关矛盾。这份清单是 `sim/catalog.js` 从代码生成的，所以它反映的是代码现状，《主线方案》是还没落地的计划。建议在方案文档开头标一下每条的状态。

### 3. 5 道菜谱没有装备就永远做不出来（中等，玩家会觉得是 bug）

炸、烤默认只能加工 1 份原料，但下面这些菜谱要求同时加工 2 份：土豆焖牛肉、葱烧土豆、牛肉蘑菇、土豆蘑菇（烤），土豆虾仁（炸）。我用规则引擎验证过：不带装备时触发 0 次，带上双面烤盘或宽口油锅才触发。菜谱的说明（`recipeCond()`）没有提到这个前提，商店照常卖。

改法二选一：说明里加一句“需要双面烤盘/宽口油锅”，或者把这几道换成炒、蒸、搅拌（默认 2–3 份）。

### 4. 菜谱强弱差距很大（中等）

用自带的 `sim/rec.js`（凑齐配料的随机手牌，比较装不装这道菜谱的得分差）重跑了一遍，每铜钱收益：

| 档次 | 菜谱 | 每铜钱 |
|---|---|---|
| 最强 | 三鲜豆腐 | 5.71 |
| | 葱花拌 | 5.64 |
| | 炸虾 | 3.97 |
| 中段 | 番茄炒蛋 | 2.36 |
| | 炒虾仁 | 1.79 |
| 偏弱 | 煎蛋（起手菜谱） | 1.13 |
| | 葱爆虾仁 | 0.43 |
| | 烤牛肉 | 0.39 |

最强和起手煎蛋差 5 倍，方案里定的标准是同价位相差不超过 15%。倍率类仍然明显强于加分类，方案第三节“分 + 倍”的问题还在。

另外有 20 道菜谱在这个测试里是 0 分，主要是四类：改规则或改牌组的（蒸蛋、土豆泥、泡发香菇、葱油、凉拌豆腐、香煎虾等）、只给铜钱的（番茄蒸虾、土豆蘑菇）、需要别的菜谱配合的（焦香豆腐、葱爆牛肉的“再触发”），以及第 3 条里缺装备的。它们不一定没用，但玩家在商店里看不出值不值，建议至少给每道一点保底分。

### 5. 挑剔食客难度不均（轻）

去掉牌组消耗后，300 局里死在各位食客手上的次数：大胃王 37、小桌客人 36、赶车的大哥 31、吃素的师傅 20、老饕 18、怕咸的老伯 14、怕油的阿姨 8、挑嘴的小孩 4。最难和最简单差约 9 倍。大胃王（每次至少 2 份原料）和小桌客人（手牌 -2）在牌少的时候尤其致命，和第 1 条叠加。

### 6. 模拟器的三种策略其实是同一种（影响后续调数值）

`sim.js` 里“smart / rand”两种策略依赖 `canOrder`、`placeOrder`（订货），但引擎里已经没有这两个函数，所以三种策略跑出来的结果一模一样（我跑了三遍，数字完全相同）。同样，`rollMarket()`（菜市场）定义了但从来没被调用，`G.market` 永远是空的。`sweep.sh` 指向的 `../cur` 目录也不存在。

方案第七节要用“专精 / 乱买 / 只买倍率”三种策略比通关率，在这之前要先把策略重写。

### 7. 其他技术债（轻）

- 外层仓库只有 1 次提交（2026-11-06），之后的改动（l1.js、菜谱扩展、小工具包等 20 个文件）都没提交。建议先提交一次，改主线前有个可以回退的点。
- `l3.js` 的 `deckIdx()` 按“牌名 + 印记”找牌组里的位置，同名同印记的牌会删到第一张，目前不影响结果，但以后加“单张牌成长”之类的机制会出错。
- 菜谱、伙计、食客数据全写在 l1.js 里，没有单独的数据文件。现在规模还能接受，菜谱再加一批时可以考虑拆出去。

## 三、可以拓展和修改的方向

按“改动小、收益大”排序。前三条就是你《主线方案》里已经定下的，我只是根据模拟结果排了先后。

1. **先改“出过的牌回弃牌堆”，并去掉补货包。** 这是一处改动（`consume()` 和 `fatesOf()` 的默认去向），模拟显示它单独就能把游戏从“第 2 关必死”变成可以玩下去。同时，现在有 25 样东西的效果是“放回牌组/留下”（6 道菜谱、17 位伙计、2 件装备，比如回锅肉、凉拌豆腐、护蛋阿姨、蒸手、蒸笼），改成不消耗后这些效果会失去意义，需要换成别的效果。这是这次改动里工作量最大的部分。
2. **改成 4 关通关，加终局食客。** 目标分曲线现在是按 8 关、每回合 ×1.13 增长写的，改 4 关要重新定。
3. **开局选招牌菜 + 买菜谱送配料。** 起手牌组 30 张里只能做 22/53 道菜谱（缺豆腐、鲜虾、烤、搅拌），买到其余 31 道之后要靠运气补牌。送配料能直接解决。
4. **菜谱数值统一成“分 + 倍”，修第 3 条的装备前提。**
5. **重写模拟器策略**，然后用它调第 4 条的数值和目标分。
6. 后续可以考虑的新内容（方案里没写，供你挑）：
   - 招牌菜满级后的“出师”效果，给专精一个终点奖励。
   - 食客偏好：普通回合也给一个小加成条件（比如“今天想吃辣”，带辣椒 +分），让非 Boss 回合也有变化。
   - 结算页记录每局最高的一锅和招牌菜，配合宣传图里已有的“菜谱”概念做收集图鉴。

## 四、这次顺手修的问题（Game Studios 工具本身）

检查时发现中文版里 33 个文件翻译出错：有的整个文件被替换成了翻译 AI 的回复（比如“需要写入权限才能保存文件”），有的被包在多余的 ```markdown 代码块里。这会导致对应的代理和技能（包括 balance-check、code-review、design-review、producer、qa-lead 等）无法加载。

我把能救的 15 个去掉了多余包装，保留中文；另外 18 个内容已丢失，从原版恢复成英文。现在 48 个代理、37 个技能、11 条规则的文件头都能正常识别。这些改动只在 `Claude-Code-Game-Studios` 文件夹里，没碰你的游戏文件。
